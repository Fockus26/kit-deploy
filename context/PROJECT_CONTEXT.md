## Summary

A Vercel of its own on César's VPS: a preview per PR, deploy on merge, variables per
environment, HTTPS domains, instant rollback, logs, metrics, alerts and cron, with a dashboard
and an SSH CLI the kit's agents drive. Replaces Vercel for every kit project (Next.js first).

## Project type

dashboard/app + infrastructure (server scripts, a root agent, a CLI).

## Business

- **What it does:** builds in GitHub Actions, runs each deployment as a Docker container behind
  Caddy on the VPS, and shows and controls it all from `deploy.fockus.dev`.
- **What the site must achieve:** support — run César's projects with no per-seat or per-use bill.
- **Main action:** see that a deployment is up and act on it (redeploy, rollback, change a variable).

## Target audience

César only (v1): a frontend developer who runs a dozen kit projects, and the kit's agents over
SSH. v2: collaborators and a read-only client view.

## Way of working

- Dark mode: yes — dark first, plus light (`prefers-color-scheme` + a switch) (D007)
- Parent branch: no, units branch off `main` — see `GIT_STATE.md`
- **VPS:** every step that changes the server is shown to César with its exact commands and run
  only with his OK for that unit. Scripts are tested first in Docker (`--test`), like the kit's `bootstrap.sh`.

## Particulars

- The VPS (4 cores, 8 GB, 100 GB, no provider backups) also runs unrelated containers (gaby,
  evolution_*) that count against the RAM: never touch them, measure them.
- certbot renews `db.fockus.dev` in standalone mode on :80 today: it moves to webroot **before**
  Caddy listens (brief, Traps). Losing that certificate cuts every project from its database.
- Secrets: AES-256-GCM, master key `/etc/kit-deploy/master.key` (root), copy in César's password
  manager. The agent never prints a secret; `env set` reads stdin in César's terminal.
- Until `ssh kit-vps kit-deploy version` answers, every project stays on Vercel.
- First real project: maranatha on `maranatha.fockus.dev` (D004).
